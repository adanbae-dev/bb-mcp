# 의존을 없앤 게 아니라 옮겼다

## 테스트를 추가했는데 개수가 그대로였다

```
$ npm test
ℹ tests 186      ← 방금 2개를 추가했는데
ℹ pass 186
```

`package.json` 을 열어 보니 이랬다.

```json
"test": "node --test ./test/lib.test.mjs ./test/integration.test.mjs ./test/manifest.test.mjs"
```

파일 세 개가 박혀 있었다. **새 테스트 파일은 실행되지 않는다.** 오류도 경고도 없다.
추가한 사람은 통과했다고 믿는다.

이런 걸 조용한 실패라고 부른다. 터지는 버그는 금방 찾지만, 이건 아무 일도 안 일어나는
것처럼 보인다. 그래서 목록에서 지웠다.

```json
"test": "node --test \"test/**/*.test.mjs\""
```

그리고 왜 이 형태를 골랐는지 문서에 적었다.

> 따옴표 글롭은 **Node 가 직접 확장하므로 셸에 의존하지 않는다.**
> 디렉터리 지정(`node --test ./test`)은 Node 24 에서 모듈로 해석돼 실패한다.

## 이 문장은 참이다. 그리고 버그를 만들었다

몇 릴리스 뒤에 CI 를 붙였다. 테스트 191개를 만들어 놓고 PR 에서 안 돌고 배지도 없었기
때문이다. 매트릭스를 Node 18·20·22·24 로 잡았다 — README 가 "Node 18+" 라고 주장하는데
그 주장이 검증된 적이 없었다.

첫 실행 결과.

```
node 18  ✖      node 22  ✔
node 20  ✖      node 24  ✔

> node --test "test/**/*.test.mjs"
Could not find '/home/runner/work/.../test/**/*.test.mjs'
```

`--test` 의 **네이티브 글롭은 Node 22 부터**다. 그 아래에서는 패턴이 아니라 파일 이름
하나로 읽힌다.

## 문제는 이유가 틀린 게 아니었다

"셸에 의존하지 않는다" 는 정확한 서술이다. 셸 글롭은 `sh` 가 확장하므로 Windows `cmd`
에서 깨지고, 네이티브 글롭은 그렇지 않다. 그 판단은 맞았다.

**빠진 것은 다음 질문이다 — 그래서 무엇에 의존하게 되는가.**

```
셸 글롭      → 셸에 의존       (Windows cmd 에서 깨진다)
네이티브 글롭 → Node 버전에 의존 (22 미만에서 깨진다)
```

의존을 **없앤** 게 아니라 **옮긴** 것이다. 그리고 옮긴 자리가 더 나쁜 쪽이었다 —
이 도구는 macOS·Linux 용이라 셸은 늘 있지만, Node 버전은 사용자마다 다르다.

## 왜 못 봤나

내 머신에는 Node 24 만 있다. `nvm` 이 있어도 평소에 한 버전으로 산다.

**내 머신은 하나의 설정이다.** 그 위에서 통과하는 것은 "이 조합에서 통과한다" 는
뜻이지 "동작한다" 는 뜻이 아니다. 그런데 문서에는 "Node 18+" 라고 적어놨다 — 한 번도
확인하지 않은 채로.

여기서 두 가지가 겹쳐 있었다.

- **검증되지 않은 호환성 주장.** README 가 최소 버전을 말하는데 근거가 없었다
- **그 주장을 깨뜨리는 변경.** 테스트 러너를 고치면서 사실상 최소 버전을 22 로 올렸다

둘 다 조용하다. 아무도 구버전에서 돌려본 적이 없으니까.

## 고친 것과, CI 가 한 일

```json
"test": "node --test test/*.test.mjs"
```

`**` 를 뺐다. 테스트가 전부 `test/` 바로 아래에 있어 필요가 없었다. 셸 글롭은 전 버전에서
돈다. 수정 후 18·20·22·24 **전부 통과** — README 의 주장이 그제서야 사실이 됐다.

CI 를 심은 목적은 "테스트를 돌리는 것" 이었는데, **첫 실행이 한 일은 문서의 거짓말을
찾은 것**이었다. 테스트 191개는 원래 통과하고 있었다. 새로 밝혀진 것은 그게 **어디서**
통과하는가였다.

## 남는 규칙 두 개

**의존을 없앴다고 쓸 때는 어디로 옮겼는지 같이 쓴다.** 대부분의 "제거" 는 이동이다.
없앴다고 적으면 옮겨간 자리를 아무도 안 본다.

**호환성은 주장하는 순간 검증 대상이 된다.** "Node 18+" 를 README 에 적었으면 18 에서
돌려야 한다. 안 돌릴 거면 적지 않는 편이 낫다 — 틀린 최소 버전은 없는 것보다 나쁘다.
그것을 믿고 설치한 사람이 첫 명령에서 막히고, 그 사람은 원인을 자기 환경에서 찾는다.
