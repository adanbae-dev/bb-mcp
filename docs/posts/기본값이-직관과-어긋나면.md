# 기본값이 직관과 어긋나면, 틀린 건 직관이 아니다

## "그러면 repos 를 지정하지 않으면 접근 안 하는 거지?"

아니라고 답해야 했다.

내가 만들던 Bitbucket MCP 서버는 허용 저장소 목록(allowlist)으로 접근 범위를
제한한다. 그런데 아무 설정도 없으면 `open` 모드로 떴다. 토큰 스코프 전체가
열린다는 뜻이다. 그 계정이 읽을 수 있는 모든 저장소.

기동할 때 stderr 로 경고는 남겼다. MCP 서버의 stderr 를 들여다보는 사람은 없다.

## 빈 문자열이 '전부 허용'이었다

더 나쁜 쪽은 이거였다.

```bash
BITBUCKET_ALLOWED_REPOS=""     # 아무것도 허용 안 함? → 전부 허용
```

목록을 비우면 아무것도 허용하지 않는다는 게 자연스러운 읽기다. 구현은 반대였다.
"값이 없음 = 제한 없음" 이라는 분기 하나의 결과다. **항목이 0개인 allowlist와
allowlist가 없는 상태를 같은 것으로 뭉갰다.** 이 둘은 정반대 의도인데.

## "문서에 쓰여 있었다"는 변론이 못 된다

기능은 사양대로 동작했다. README 에도 적혀 있었다. 그래도 이건 버그다.

기본값은 사용자가 안 읽었을 때 적용되는 값이다. 읽고 고른 값이면 그건 기본값이
아니라 설정이다. 그래서 "문서에 있다"로는 기본값을 변호할 수 없다 — 문서를 안 본
사람에게만 기본값이 작동하기 때문이다.

그리고 첫 추측에서 반대로 짚었다는 건 취향이 아니라 데이터다. 물어본 사람은
이 서버를 나와 같이 만들던 사람, 즉 가진 맥락이 가장 많은 사용자였다. 그 사람이
틀리게 추측하면 나머지는 전부 틀린다.

## 고친 것

- 설정이 없으면 `denied` — 전부 차단. 서버는 그대로 뜨고, 여는 방법을 응답으로 준다
- 전체 개방은 `BITBUCKET_ALLOW_ALL_REPOS=true` 로 **명시해야** 한다

죽지 않고 뜨는 쪽이 중요하다. 기동 실패로 처리하면 진단 툴도 같이 죽어서, 왜 안
되는지 볼 수단이 사라진다. 차단은 하되 말은 할 수 있어야 한다.

## 기본값을 뒤집으면 없던 상태가 생긴다

여기서 회귀가 하나 나왔다.

`bb_allowlist_list` — allowlist 상태를 보여주는 툴이다. 이게 `denied` 모드에서
아예 실행되지 않았다. 공통 `guard()` 가 진입 시점에 allowlist 를 해석하는데,
설정이 없으면 거기서 예외가 났다.

**상태를 설명해야 할 바로 그 상황에서, 상태 설명 툴이 안 떴다.**

이전에는 이 경로가 존재하지 않았다. 설정 없음 = `open` 이었으니 `denied` 로 진입
하는 호출 자체가 없었다. 기본값을 뒤집으면서 전에는 도달 불가능하던 상태를
만들었고, 그 상태를 지나는 코드 경로는 아무도 밟아본 적이 없었다.

더 뼈아픈 건 같은 처방을 `bb_doctor` 에는 이미 해뒀다는 점이다. 이유까지 코드에
주석으로 남겨놓고, 형제 툴에는 적용하지 않았다.

## 남는 것

기본값은 문서로 검증되지 않는다. 질문으로 검증된다. 사양을 모르는 사람에게
"설정 안 하면 어떻게 될 것 같냐"고 묻고, 답이 구현과 다르면 고칠 대상은 구현이다.

그리고 기본값을 뒤집을 때 점검할 것은 기능이 아니라 **새로 생긴 상태**다. 전에는
못 가던 곳에 이제 갈 수 있게 됐고, 그 길은 한 번도 밟히지 않았다.
