# 대상 고르기 — 저장소 감지 · 선택창 · PR 목록 표

| 결과 | 할 일 |
|---|---|
| `repo` 있고 `allowed: true` | 쓴다. **어느 저장소인지 한 줄로 밝히고** 진행 |
| `repo` 있고 `allowed: false` | 멈춘다. allowlist 추가 + 세션 재시작이 필요하다고 알린다 |
| `other_remote_host` | Bitbucket 이 아니다. GitHub 이면 `gh` 안내 |
| `is_git: false` | `AskUserQuestion` 선택창 |

**remote 이름이 `origin` 이라고 가정하지 않는다** — 실측한 저장소에 remote 가 4개
있었고 GitHub 3 + Bitbucket 1 이었다. 툴이 전부 훑어 고른다.

선택창은 평문으로 되묻는 것보다 낫다(이름을 기억해 타이핑하지 않아도 된다).
옵션은 2~4개이므로 **열린 PR이 있는 저장소를 맨 앞에**, 그다음 최근 갱신순으로
자른다(`bb_pr_inbox()` + `bb_repos()`). 각 옵션 `description` 에 고를 근거를 넣는다
(`열린 PR 1건 · 방금 갱신`). allowlist 가 1개면 묻지 않고 한 줄로 밝힌다.
`allowed: false` 면 선택창을 띄우지 않는다 — 그 저장소를 쓰려던 것이다.

### PR 목록 표

목록 규약의 단일 소스는 **`/bb-prs` 명령**이다. 여기서는 그대로 따른다. 요점만:
마크다운 표(원본 JSON 금지) · 열 순서 `#`·제목·작성자·갱신 고정 · **15행까지**
(넘으면 `최근 15건 / 전체 N건`) · 갱신은 `MM-DD[ HH:MM]` 으로 쓰고 **상대시간
금지**(현재 시각을 모르는 채 `N시간 전` 을 쓰면 지어내는 것) · 제목은 티켓 접두사
**뒤부터** 40자 · `comment_count > 0` 이면 `💬N` · 승인 상태는 넣지 않는다(목록
응답에 없다) · 제목의 `|` 는 이스케이프한다(외부 입력).
