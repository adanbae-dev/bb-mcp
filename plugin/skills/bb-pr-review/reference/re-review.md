# 재리뷰 — 이전 리뷰가 있을 때

머리말을 바꾼다.

```
## 재리뷰 · #0000 (머지됨) · `a1b2c3d4e5f6`
이전 리뷰(`0f1e2d3c4b5a`) 이후 커밋 1개 · config.ts +73 −26
```

그다음 **「이전 리뷰 처리」 표** — 이전 지적 1건당 1줄.

| 상태 | 뜻 |
|---|---|
| 닫힘 | 더 이상 성립하지 않는다 |
| 남음 | 그대로거나 영향만 줄었다 |
| 되돌림 | 지적한 코드가 **기능째 사라져** 닫혔다 |

0.23.0 이전 리뷰의 `🔴 1-1` 같은 번호는 **게시된 그대로 인용한다.** 새 등급으로
다시 매기지 않는다 — 답글이 그 번호를 가리키고 있다. 새로 쓰는 지적만 `P1-1` 로 매긴다.
P2 가 반영되지 않았는데 사유 답글도 없으면 「남음」 에 `사유 없음` 을 붙인다.

「지적 목록」 표는 이 표 **다음에, 이번에 새로 쓴 지적만** 넣는다. 이전 지적의 상태는
「이전 리뷰 처리」 표가 맡는다 — 두 표에 같은 지적을 두면 상태가 두 곳으로 갈린다.
새 지적이 없으면 목록 표를 생략한다.

**「되돌림」은 그냥 넘기지 않는다.** 요구한 수정으로 닫힌 것과 기능을 걷어내서 닫힌
것은 다르다. 후자면 **PR 이 원래 잡으려던 것이 아직 잡히는지** 다시 보고, 결과를
새 지적(`[기록]` 또는 P1)으로 쓴다 — 실물 재리뷰에서 P1 1건이 요구한 인자를 추가해서가
아니라 검사 자체를 걷어내서 닫혔고, PR 이 막으려던 시나리오가 다시 통과하게 됐다.

**MERGED 면** 머리말에 `(머지됨)` 을 적고 `## 종합 의견` 을 머지 가부가 아니라
후속 조치로 쓴다 — `머지 후 설명 수정 권장 — 코드는 그대로 둔다`.
