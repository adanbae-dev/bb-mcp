`bb_doctor` 툴을 호출해 설정을 점검하고, 결과를 사람이 읽기 쉽게 정리한다.

$ARGUMENTS 가 `quick` 이면 `probe: false` 로 네트워크 호출 없이 설정만 검사한다.

보고 방식:
- 문제가 없으면 한두 줄로 끝낸다. 항목을 전부 나열하지 않는다.
- 문제가 있으면 각 항목의 `fix` 를 실행 가능한 명령으로 제시한다.
- `restart_required` 나 "세션 재시작" 이 필요한 항목은 따로 묶어 알린다.

`bb_*` 툴이 아예 보이지 않으면 서버가 등록되지 않았거나 연결에 실패한 것이다.
그때는 `bb_doctor` 도 부를 수 없으므로 사용자에게 이렇게 안내한다.

```bash
claude mcp get bitbucket     # 등록·연결 상태
./setup.sh                   # 처음 설정하거나 다시 맞출 때
```

허용 저장소만 보려면 `bb_allowlist_list` 가 더 짧다.

## 출력

원본 JSON을 붙이지 않는다.

**정상이면 한두 줄로 끝낸다.** 항목을 전부 나열하지 않는다 — 다 통과한 점검을
읽는 데 시간을 쓰게 하지 않는다.

```markdown
✔ bb-mcp 정상 · 스코프 3개 · 허용 저장소 13개 · 코멘트 게시 켜짐
```

**문제가 있을 때만 표로 낸다.** 통과 항목은 접어서 개수로만 말한다.

```markdown
## bb_doctor · 문제 2건 (점검 6건 중)

| | 항목 | 상태 | 조치 |
|---|---|---|---|
| 🔴 | 토큰 | 128자에서 잘림 | 키체인에 다시 저장 (아래) |
| 🟠 | 허용 저장소 | 미설정 — 전부 차단 | 파일 작성 후 재시작 |

나머지 4건 통과: 인증 · 스코프 · 코멘트 게이트 · API 주소
```

- `fix` 는 표 안에 밀어넣지 않는다. 표 아래 코드블록으로 **복사해 붙일 수 있게** 낸다
- `restart_required` 항목은 따로 묶고 **재시작이 필요하다는 말을 빼먹지 않는다**
- 🔴 는 지금 안 되는 것, 🟠 는 되지만 위험하거나 반쪽인 것
- 토큰 값은 어떤 형태로도 옮겨 적지 않는다. 툴이 안 주고, 받아도 출력하지 않는다
